# Galeri.TR feature parity in WOW

## Scope and evidence

The comparison covers the complete public source of Galeri.TR’s main page (39,182 lines), accounting page (5,144 lines), files page (2,638 lines), and service worker (218 lines), and the current WOW repository. The source provides application behavior and table names. Live record counts, storage contents, and identities require a separately authorized export from the owner of the source project. The four snapshots contain no business dataset suitable for migration. Feature implementation, existing data import, deployment and production verification are separate milestones.

WOW’s existing product, company, invoice, payment, manufacturing, archive, task, material, label, search, account and appearance screens remain the primary user experience. New screens should use the same navigation, responsive cards, field styles, theme variables, five locales, direction and accessible controls. One Supabase project owns business state, membership, assets and notifications.

## Dependencies and correctness repairs

- Replace all direct source-project URLs, anonymous table access, public storage URLs, EmailJS service/template configuration and client-directed push endpoint with the verified primary API. Client-supplied username, room, workspace, price, permissions and sort order alone do not authorize an operation.
- Source main table families include inventory, orders, user orders inventory, user sales log, user print settings, users/sessions/OTP, admin accounts/profiles, outbound messages, push subscriptions, app settings, dimension fields, home cards, hero slider, group rooms/members/messages/read status, mentions, forwards, reactions, stars, per-user hides, typing, drafts and user chat settings. The source declares an older admin chat table as well. Source media uses home-images, chat-media and user-files buckets. Accounting references sixteen acc-prefixed tables plus local audit state.
- Replace root/global DOM listeners, second service worker/cache purge, device-password storage, client-generated OTP, hardcoded login fallback, unfiltered realtime subscriptions and hardcoded brand URLs. Use normal app navigation and authenticated refresh. Browser sessions signing out or changing account must clear visible private state and discard in-flight responses.
- Original media fallbacks refer to up6, Wix, placehold.co, Pinterest, GitHub-hosted images and Pixabay audio. Font Awesome/Google Fonts, JSZip, ExcelJS, html2canvas, jsPDF, JsBarcode and QR libraries are remote in the source. Use current app icons/branding and local export components or pinned local licensed code. Native user-initiated WhatsApp, email and OS sharing can open their destination without becoming a business-data backend.
- Source accounting updates cashbox and transaction separately, mutates local state before acknowledgement, sometimes writes only the first 50/100 records and omits remote tombstones. Transfer and metal deletion remove history without compensating the cash/holding. Use transactionally checked commands and idempotent retries. Source sales and stock reservations also span unrelated client writes.
- Source uploads support arbitrary types through public URLs; document previews must isolate active content. Enforce declared size/type, workspace limits, signed object access and cleanup of failed uploads. Source bulk ZIP silently skips failed files; report errors without claiming a complete archive.
- Direct browser link-sharing exposes file bytes to recipients in the old implementation. Preserve the action with user-initiated sharing of a downloaded file or an explicit scoped, expiring share grant. Private metadata, group membership and folder ownership stay enforced on subsequent reads.
- Independent current-app finding fixed in this branch: removed the client-shipped PDF private signing key and false certification marker. Each encrypted invoice now receives independent random owner-permission material; the unchanged openable invoice is not represented as a trusted company digital signature. Actual exported pages pass strict PDF parsing/decryption and a rendered fixture check.

## Integration and acceptance order

1. Establish server capability names, scoped customer and staff membership rights, membership/session verification at commit, private tables/storage and immutable operation IDs. Chat and customer data cannot pass through the generic six-store broadcast feed.
2. Implement isolated catalog/order, collaboration/files and finance/payroll modules under the current URL. Keep existing product, company, invoice and cashbox records canonical. Attach permitted routes and navigation through the primary shell.
3. Run transactional tests covering permission changes, simultaneous orders, insufficient stock, quantity corrections/reversals, retry, payroll duplicate prevention, transfers, member removal, message expiration and file isolation. Verify branded exports, locale/RTL, SW update/offline behavior and private-screen cleanup in real browsers.
4. Reconcile any owner-authorized export with explicit record counts, typed IDs, currency semantics, foreign keys, permissions and media hashes. Keep ambiguous mappings reviewable. User data on the old origin cannot be read by the new origin through browser storage.
5. Verify the named production origin with distinct owner, employee and customer accounts, plus an intentionally unauthorized second user. Record observed route and business outcomes; inspect network destinations. The old repository must remain available until feature and data verification are complete and its owner authorizes retirement.

## Gallery implementation handoff

The native gallery registers four routes through the primary shell. `gallery` lists published projections of canonical WOW products. `gallery-studio` stages stock changes with revision checks, manages collection cards, slides, specifications and print/social branding. `gallery-orders` manages workspace orders. `my-orders` provides purchaser-only orders, holdings, resale documents, sale reversals and print settings. Order and stock output includes PDF, XLSX with photographs, print, share, and individual image/specification or ZIP download as appropriate. Gallery assets use immutable paths inside the primary private bucket.

The Edge registry exports `createGalleryActions` from `supabase/functions/wow-cloud/modules/gallery.mjs`. The database entry point is `wow_gallery_service(text,jsonb)` from `supabase/modules/gallery.sql`. The mutation ID is `commandId` (UUID). A changed draft after an ambiguous network failure calls the online-only `gallery.command.review`; a transaction either confirms the old receipt or marks that old command abandoned before the new submission. The browser retains each cart under its workspace and account. An offline queued write keeps the form/cart in place. Only the authoritative response triggers a receipt, clears the cart or reports a sale. The common offline transport owns the synchronized device cache, queued delivery and revocation handling.

The worker integration consumes pending rows in `wow_gallery_notification_outbox`. Events identify one recipient, workspace, business record and revision, and deduplicate across retries. The shared worker must call `wow_gallery_notice_payload(id,recipient_id)` immediately before delivery, suppress a null result and pass approved results to `formatGalleryNotice(payload, language)`. The function emits bounded localized copy and an authenticated route target. A private staff note is never a customer notification. Actual Web Push delivery requires the shared worker subscription, relay and real device verification.

The local executable gates use an in-memory PostgreSQL engine with the production SQL and explicit substitutes for provider-owned integrations. The DOM flow uses registered UI controls and real Edge and SQL code. It exercises an owner publishing an existing product, a queued and then confirmed customer order using the same UUID, owner release, purchaser resale and reversal. It also checks role visibility, changed quote, refusal of conflicting stock, forbidden cancellation after resale, stale push eligibility, rejection of abandoned late writes, and distinct numeric and text product IDs. Pure tests check currency totals and valid PDF cross-reference offsets.

The gallery browser scenario in `tests/gallery.browser.cjs` uses a synthetic in-memory transport without contacting a production workspace. In this executor Chromium fails at startup when creating its process-singleton socket. Browser-level visual, native file-share, print, camera, connected-domain, delivered push and physical device checks remain open. Authenticated studio social metadata also needs the primary deployment to publish an intentional same-origin public representation for link crawlers. These boundaries apply independently of the successful SQL and DOM tests.
