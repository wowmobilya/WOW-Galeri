# فحص تاريخ Galeri.TR قبل النقل

## ما أُنجز وما لم يُنجز

أضيفت أداة محلية للقراءة فقط: `scripts/galeri-transfer-preflight.mjs`. تفحص الجرد، أعداد السجلات، المعرّفات، خرائط الحسابات والمنتجات وملكية الملفات وبعض العلاقات التي يثبتها الكود العام. تنتج تقريرًا خاصًا، ولا تتصل بأي خدمة، ولا تنفذ SQL، ولا ترفع ملفات، ولا تنشئ حسابًا، ولا تعدّل مخزونًا أو ترسل مراسلة.

**هذه ليست أداة استيراد كامل.** حتى إذا لم يظهر اختلاف في الجرد، يبقى `applyReady:false` لأن مخطط المشروع الخاص وبياناته الفعلية لم يُفحصا، ولم يُكتب محوّل معتمد لكل عائلة. خريطة الحقول أدناه هدف للمراجعة، وليست أمرًا قابلًا للتطبيق. لا يكفي نجاح اختبار اصطناعي لإعلان انتقال بيانات الشركة.

يشير الكود العام القديم إلى المشروع `sldthbnigivpsqixccah` نفسه: `index.html` عند تعريف `SUPABASE_URL` قرب السطر 8453، و`myfiles.html` قرب 1427. لم تُستخدم مفاتيحه العامة لمحاولة تجاوز رفض موصل الإدارة. يجب جرد ما يوجد بالفعل في هذا المشروع قبل الترحيل الإضافي، وعدم تصفيره. [المصدر العام](https://wowmobilya.github.io/Galeri.TR/)

## تشغيل الأداة

بعد الحصول على تصدير مصرح به، يحضّر المشغّل ملفين خاصين خارج المستودع:

```sh
node scripts/galeri-transfer-preflight.mjs /private/galeri-export.json /private/galeri-mapping.json /private/galeri-report.json
```

ملف التصدير بالشكل التالي، مع جميع العائلات المذكورة في `familyTargets` داخل السكربت. يجب أن تبقى العائلة الموجودة الفارغة `[]`، وأن تقابلها قيمة `0` من جرد المصدر؛ غيابها لا يعني أنها فارغة.

```json
{
  "projectRef": "sldthbnigivpsqixccah",
  "tables": {
    "users": [],
    "inventory": [],
    "orders": [],
    "user_files": []
  },
  "counts": {"users": 0, "inventory": 0, "orders": 0, "user_files": 0},
  "objects": []
}
```

المثال مختصر؛ سيبلغ السكربت عن العائلات غير الموجودة. الحصة القصوى 64 MiB لكل ملف JSON، و50 ألف سجل للعائلة، و100 ألف سجل إجمالًا. التصدير الأكبر يحتاج تقطيعًا متسقًا وتجميع الجرد قبل المقارنة؛ لا يجوز الاكتفاء بأول صفحة من API.

ملف الخريطة يضم `workspaceId`، وجرد الحسابات الموجودة `targetAccounts` بقيم `{id, workspaceId, role}`، ثم `accounts` بقيم `{family, sourceId, targetId, targetRole}`، حيث `family` إما `users` أو `admin_accounts`. لا تنشئ الخريطة الدور أو تغيّره؛ تطابقه مع جرد الهدف فقط. المصدر الرقمي `1` والمصدر النصي `"1"` هويتان مختلفتان.

تحتوي `targetProducts` على معرّفات المنتجات الأساسية الموجودة. تحتوي `products` على `{sourceId, targetId}`، وتشير صراحةً من `inventory.id` إلى منتج WOW. لا يُطابق المنتج باسم أو تشابه صورة. تحتوي `fileOwners` على `{sourceId, targetId}` لكل سجل من `user_files`، حتى لو كان المشغّل مالك الشركة. لا توجد ملكية افتراضية لجميع الملفات.

تتضمن كل خانة `objects` سجلًا `{bucket, path, bytes, mime, sha256}` من النسخة المستخرجة. الحاويات المعروفة `home-images` و`chat-media` و`user-files`. تفحص الأداة توافق بيانات ملف المستخدم مع الجرد، ولا تجلب أي URL ولا تثبت محتوى الكائن. لذلك يبقى `objects.contentVerified:false`؛ يجب قراءة البايتات وحساب SHA-256 فعليًا في مرحلة النسخ، ثم فحص الكائن المنقول ومقارنته بالأصل.

يُنشأ التقرير مرة واحدة بحقوق `0600`، ويرفض الكتابة فوق المدخلات أو فوق تقرير سابق. يرفض أيضًا مسارًا داخل المستودع، بما فيه المرور عبر رابط رمزي لدليل المستودع. يطبع الطرفية ملخصًا عدديًا وبصمة البيان فقط. يضم التقرير الخاص معرّفات المصدر ومواقع الاختلاف وبصمات منزوعة حقول الأسرار؛ لا يضم نصوص الرسائل أو أسماء الملفات أو كلمات المرور.

## العلاقات المثبتة والقرارات التي تحتاج مراجعة

| عائلات المصدر | الوجهة المقترحة | ما يحتاج تحققًا قبل كتابة محوّل الاستيراد |
| --- | --- | --- |
| `users`, `admin_accounts` | Auth و`wow_accounts` الموجودان عبر خريطة صريحة | تصنيف الزبون والموظف والمالك؛ تعارض أسماء المستخدمين؛ لا تُنقل كلمات المرور أو الجلسات أو OTP ولا يُوثق بريد بمجرد وجوده في الجدول القديم. |
| `inventory` | منتجات WOW الأساسية و`wow_gallery_listings` | خريطة معرّفات ذات نوع، العملة ودقة السعر، المخزون النهائي، نسخ الصور الخاصة. لا يُنشأ منتج مماثل بالاسم تلقائيًا. |
| `orders`, `user_orders_inventory` | الطلبات وخطوطها وتفضيلات المشتري | كتب المصدر الطلب والمخزون الشخصي في عمليتين منفصلتين؛ تطابق المستخدم ورقم الطلب والمنتج والكمية والحالة. لا تُخصم الكمية مرة ثانية عند نقل التاريخ. |
| `user_sales_log` | سجل إعادة البيع | تطابق مجموع `qty_sold` مع السجل الشخصي، المبيعات المعكوسة والمحذوفة وتواريخها والأسعار. لا يُصلح الفرق بإضافة قيد أو بتغيير الرصيد تخمينًا. |
| `group_rooms`, `group_members`, `group_messages` | الغرف والأعضاء والرسائل الخاصة | تعيين أسماء المصدر إلى هويات موثقة، أهلية الزبون للغرفة، مؤلف الرسالة والملفات، الردود والانتهاء والحذف. التقرير يفحص مراجع الغرف والردود لكنه لا يثبت كل هذه الحدود. |
| `admin_chats`, التفاعلات والنجوم والتحويلات والإخفاء والمشاهدات والمنشن | تاريخ المحادثة وعلاقاته | المصدر القديم يستخدم `scope`; مراجع المجموعة تُفحص، وأي نطاق آخر يُرفع للمراجعة. يلزم تحويل معرّفات الرسائل والمشاهدات ولا يجوز نسخ أرقام القراءة مباشرة. |
| `group_read_status`, `chat_drafts`, `chat_user_settings`, `admin_profiles` | مؤشرات القراءة والمسودات والتفضيلات والملفات الشخصية | خريطة الحساب والغرفة، الفرق بين مشاهدة رسالة ومؤشر القراءة، صور الحساب وخلفيات الغرف. |
| `user_files`, `local_folders` | الملفات والمجلدات الشخصية | لا يضع المصدر `owner_id` في بيانات الملف عند الرفع، بينما النظام الجديد يتطلب مالكًا. المجلدات المحلية تحتاج تصدير الجهاز أيضًا؛ وجود صفوف `user_files` وحده لا يثبت تصديرها. |
| `messages` | أرشيف مراسلات تاريخي | حالات WhatsApp القديمة `sent` تعني فتح النافذة في الكود، وليست إثبات تسليم. يبقى السجل تاريخيًا ولا يُعاد إرساله. |
| `app_settings`, `dimension_fields`, `home_cards`, `hero_slider`, `user_print_settings` | إعدادات المعرض والطباعة المسموحة | تنقية الحقول، أهداف الأقسام، العلاقات والصور. لا تتحول مفاتيح الاتصال أو HTML قديم إلى إعداد عام. |
| الجداول `acc_…` | المستورد المالي الموجود | تسلم إلى مسار المحاسبة المنفصل، مع مطابقة الأرصدة والعملات؛ لا تعالجها هذه الأداة كطلبات أو مبيعات جديدة. |

مصادر السلوك في اللقطات العامة: `index.html` بناء الطلب قرب 9860، حفظ مخزون المستخدم قرب 34553، تسجيل البيع ثم تحديث مجموع المباع قرب 35456، إرسال المراسلة قرب 18013؛ `myfiles.html` بيانات الرفع قرب 2108. هذه اللقطات تثبت ما كتبه العميل، ولا تحل محل مخطط قاعدة البيانات والقيود والجداول الفعلية. [مصفوفة الميزات](galeri-feature-merge.md)

تستبعد الأداة بالكامل `user_sessions` و`otp_codes` و`push_subscriptions` و`chat_typing_status`. تُحذف حقول كلمات المرور والمفاتيح والأسرار من مادة البصمة. لا تُنسخ هذه المواد ضمن عضوية جديدة. لا يُفسر وجود خريطة في ملف محلي باعتباره تفويضًا موقعًا من المالك أو إذنًا إداريًا حيًا.

## ما يلزم بعد عودة الوصول

1. جرد مخطط المصدر ومفاتيحه وقيوده وسياسات الوصول والجداول والحاويات وأعدادها في لحظة متسقة، وأخذ نسخة قبل التعديل. نسخ قاعدة البيانات لا تشمل بايتات Storage؛ تُنسخ تلك البايتات مستقلة. [توثيق Supabase للنسخ](https://supabase.com/docs/guides/platform/backups)
2. تصدير بيانات أجهزة WOW الأصلية والمجلدات المحلية، ثم تحديد خرائط الحسابات والمنتجات والملفات ومراجعة جميع الاختلافات.
3. بناء محوّل لكل عائلة مثبتة مع معاملات، سجل خريطة ومعرّفات عملية قابلة للإعادة، وفحص تعارض مع حالة الهدف قبل الالتزام. لا يوجد هذا المحوّل الشامل في هذه الأداة.
4. تشغيل المعاينة في نسخة معزولة، ومقارنة الأعداد والعلاقات والمخزون والمبيعات والعملات وبصمات المرفقات. فحص الدخول بحساب زبون وموظف ومالك.
5. نقل البيانات المعتمدة دون إرسال إشعارات أو مراسلات تاريخية، ثم إعادة المطابقة والاحتفاظ بالنسخة الأصلية ومسار رجوع. لا يُحذف مستودع Galeri.TR أو الجداول الأصلية حتى قبول النقل.

التحقق المحلي: `node --test tests/galeri-transfer-preflight.test.mjs`. تغطي الاختبارات المعرّفات ذات النوع، الأسرار والجلسات المستبعدة، غياب التصدير مقابل الجدول الفارغ، الحسابات والملكية الصريحة، العلاقات المتعارضة، الكائنات غير المطابقة، وحماية ملفات المخرجات. جميع البيانات المستخدمة في الاختبار اصطناعية.
